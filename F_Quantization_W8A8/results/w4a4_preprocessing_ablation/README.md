# W4A4 MNIST preprocessing comparison

The LeNet-5 training, FP32 evaluation, activation calibration and HLS MNIST
data generation all use bilinear `Resize((32, 32))`. That pipeline is the
canonical W4A4 evaluation condition.

The earlier software result used `Pad(2)` and is retained as a preprocessing
ablation. It must not be described as the baseline accuracy of the LC2 hardware
optimization.

Run both conditions and compare them from `F_Quantization_W8A8`:

```bash
python evaluate_w4a4_int32.py --preprocess pad --device cpu
python evaluate_w4a4_int32.py --preprocess resize --device cpu --compare-hls-q40
python compare_w4a4_preprocessing.py
```

Each evaluation writes an accuracy summary, JSON metadata, a confusion matrix
and all 10,000 sample predictions. The comparison directory records every
prediction transition between Pad and Resize. The Resize directory also checks
the per-sample software prediction against the Q40 integer reference used by
the HLS source and checks its confusion matrix against the stored HLS result.

## Results

| Pipeline | FP32 | W4A4 | W4A4 agreement with FP32 |
| --- | ---: | ---: | ---: |
| Pad(2) ablation | 98.82% | 97.46% | 97.99% |
| Bilinear Resize(32, 32) | 99.30% | 98.11% | 98.53% |

Resize changes 230 of the 10,000 W4A4 predictions. It corrects 136 samples that
Pad classified incorrectly and makes 71 previously correct samples incorrect,
for a net gain of 65 correct predictions, or 0.65 percentage points. A further
23 samples remain wrong with a changed predicted class; 95 remain wrong with
the same class. The other 9,675 samples are correct under both pipelines.

For Resize, the software W4A4 output and the Q40 reference have zero input,
logit and predicted-label mismatches across all 10,000 samples. Their confusion
matrix is identical to the stored HLS C-simulation matrix, which also reports
9,811 correct samples. The `hls_q40_prediction` columns are generated by the
bit-accurate Python reference; they are not a newly captured RTL trace.
